# Red River Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a "Red river" table toggle. While the latest river card is red, each board that ends red gets another card with its own betting round, until a black card lands or the deck can't spare one.

**Architecture:** The engine gets one new street, `"extra"`, plus a round counter. Extra rounds are dealt by one helper that live play, run-outs, run it twice and rabbit hunt all share, so the rule lives in one place. Protocol and server pass the new fields through, and compute rabbit-hunt backs so no hidden colour leaks. The web adds the toggle, the badge, round names, and a felt layout that handles boards of any length.

**Tech Stack:** TypeScript, pnpm workspaces, Vitest + fast-check, Zod, Cloudflare Durable Objects, Next.js + Tailwind, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-07-red-river-design.md` (read it first; section numbers below refer to it). Also `SPEC.md` and `CLAUDE.md`.

## Global Constraints

- Branch `red-river`, local only. Don't push and don't run `wrangler deploy`.
- Engine: no I/O, no `Date.now`, no `Math.random`, no `console`. State stays JSON-serializable. Chips are integer cents.
- With `redRiver` off or absent, every hand deals, settles and replays exactly as today. Existing tests pass unchanged.
- Red = suit 1 (diamonds) or 2 (hearts). Black = 0 (clubs) or 3 (spades).
- Deck math (`cardsNeeded`, `validateDeck` needed count) is unchanged. It reserves 5 board cards per board per run, and never reserves extra cards.
- An extra round is all or nothing. If the deck can't spare one card for every board (and run) that ends red, none get one, and `redRiverStopped` becomes true.
- Copy, verbatim: round name `Red river N`. Log note `No cards left: red river stops.` Toggle label `Red river`, help line `A red river deals another card, with betting, until a black one.` Disabled reason `Tic-Tac-Toe has no single river card.` Badge `RED RIVER`, or `RED RIVER N` during extra round N.
- Every engine change gets Vitest tests. Invariants get fast-check properties.
- Done means `pnpm test`, `pnpm typecheck` and `pnpm --filter web e2e` all pass. Commit after each passing task.

## Review Focus

1. **Toggle off is byte-identical.** A recorded hand from before this change (no `redRiver` key) replays to the same states. Pinned in Task 4 (`replays an old record identically`).
2. **Timeouts and leavers in extra rounds.** A disconnected, kicked or leaving player whose turn comes in an extra round gets auto-check/fold, just like on the river. Pinned in Task 5 (`times out in red river 1`).
3. **Settings changed mid-hand.** Turning the toggle on or off during a hand changes nothing until the next hand. Pinned in Task 5 (`redRiver change applies next hand`).
4. **Stale actions across rounds.** A `seq` from river betting, arriving after red river 1 has started, is dropped. Pinned in Task 5 (`drops a river action sent before red river 1`).
5. **Rabbit backs never leak colour.** Before a hunt, the felt shows missing base cards + 1 only when a red card is visible, never the real extra count. Pinned in Task 3 (`rabbitBacks`) and Task 5 (`rabbitBacks don't reveal extra count`).

### Task 2: Engine: extra rounds in live play

**Files:**
- Modify: `packages/engine/src/hand.ts`, `packages/engine/src/board.ts`
- Test: `packages/engine/test/redriver.test.ts`

**Interfaces:**
- Consumes: `isRed`, `HandConfig.redRiver` (Task 1)
- Produces:
  - `Street` gains `"extra"` (order: preflop, flop, turn, river, extra, complete)
  - `HandState.extraRound: number`: 0 until the first extra round, then N during red river N. Kept after the hand completes.
  - `HandState.redRiverStopped: boolean`: true once an extra round was skipped for lack of cards
  - `LogEntry.extraRound?: number`: set on every entry whose `street` is `"extra"`
  - `wantsRedRiverCard(config: HandConfig, board: readonly Card[]): boolean`: `!!config.redRiver && board.length >= boardSize(config.variant.board) && isRed(board.at(-1)!)`
  - `boardFinished(config: HandConfig, board: readonly Card[]): boolean`: base board complete and `!wantsRedRiverCard`
  - board.ts: `streetOfPosition` returns `"extra"` for positions ≥ `boardSize`. `streetWithDealt` returns `"extra"` for dealt > `boardSize`. New `extraRoundOfPosition(layout, position): number` returns `position - boardSize(layout) + 1`, and 0 for base positions. This is correct because a black card is final, so a board's k-th extra card is always dealt in round k.
  - internal `dealExtraRound(s: HandState, boards: Card[][][]): boolean`: collect every board, across the runs given, that `wantsRedRiverCard`, in run order then board order. If there are none, return false. If `deck.length - deckIndex < count`, set `redRiverStopped = true` and return false. Otherwise deal one card to each, increment `extraRound`, and return true.

**Behaviour** (`advance`): when betting closes on `"river"` or `"extra"`, check run it twice first (Task 3 covers eligibility). Then call `dealExtraRound(s, [s.boards])`. If it dealt, set `street = "extra"`, reset bets the way `dealNextStreet` does, and continue the loop from the button. Otherwise `finish(s)`. Today's `if (s.street === "river") finish` goes away.

### Task 3: Engine: run-outs, run it twice, rabbit hunt

**Files:**
- Modify: `packages/engine/src/hand.ts`
- Test: `packages/engine/test/redriver.test.ts`

**Interfaces:**
- Consumes: `dealExtraRound`, `wantsRedRiverCard`, `boardFinished` (Task 2)
- Produces:
  - `runOutAndFinish(s, runs)` deals run 1's base streets, then run 2's base streets (today's order), then calls `dealExtraRound(s, runs === 2 ? [s.boards, s.secondRun!] : [s.boards])` until it returns false, then finishes.
  - `canRunTwice`: true when `missingBase > 0 || redBoards > 0`, and `deckIndex + 2 * missingBase + 2 * redBoards <= deck.length`. Here `redBoards` is the number of boards for which `wantsRedRiverCard` is true. The Pineapple guard becomes "false on preflop or flop" (river and extra are now allowed).
  - `rabbitCards(s)`: deals the remaining base streets onto copies of the boards, then extra rounds all or nothing, on a scratch copy (never mutating `s`). It returns only the new cards per board. It returns empty lists when `secondRun` is set or every board is `boardFinished`.
  - `huntable(s: HandState): boolean`: complete, no second run, and `rabbitCards(s)` holds at least one card.
  - `rabbitBacks(s: HandState): number[]`: per board, `min(rabbitCards(s)[b].length, missingBase[b] + (wantsRedRiverCard(config, board) ? 1 : 0))`.

- [ ] **Step 1: Write failing tests**, `describe("red river run-outs")`:
  - `all-in on the flop runs once through red rivers`. Turn and river come out, then extras while red. The board ends black and the result is settled.
  - `run it twice: each run extends on its own`. Run 1 river black, run 2 river red then black. Run 1 has 5 cards and run 2 has 6. Deck order is run 1 base, run 2 base, then run 2's extra card.
  - `run it twice offered on a red river`. The last all-in comes during river betting, the river is red and the mode is `"ask"`. `ritOffer` is set.
  - `run it twice not offered on a black river`. The hand completes.
  - `rabbit after a fold on a red river`. `huntable === true`, and `rabbitCards` shows the extras through the first black card.
  - `rabbitBacks`: a fold on the flop with toggle on gives `[2]` whatever the deck holds. A fold during red river 1 (latest card red) gives `[1]`, even when the hunt would show 3. A fold on a black river gives `huntable === false`.
